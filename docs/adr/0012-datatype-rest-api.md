# ADR 0012: DataType REST API

## Status

Accepted

## Context

NETAUTO now needs a stable HTTP boundary for the DataType engine while keeping
transport concerns, orchestration, domain logic, and persistence separated.

## Decision

The REST API is the public interaction boundary, and the CLI will consume REST
only. FastAPI routers remain thin transport adapters while the application
service owns orchestration. A DataTypeUnitOfWork Protocol decouples the
application layer from SQLAlchemy, and the existing SqlAlchemyUnitOfWork
structurally implements that port. Pydantic v2 is used only for static API
DTOs; dynamic DataTypes remain domain plus JSON Schema concepts. The request
boundary is strict and performs no implicit coercion. The domain remains
authoritative for identifier, constraint, and lifecycle rules. The API exposes
logical DataType identity separately from exact versions. There are no
latest/current semantics, and multiple PUBLISHED versions may coexist. PUT
draft revision is full replacement. Create-next explicitly names
`source_version`. Error responses use a stable NETAUTO envelope. OpenAPI
generated by FastAPI is the canonical API contract. There is no import-time DB
initialization and no CLI in M1.1.9.

## Consequences

Transport logic stays thin, persistence remains swappable behind the
application layer, and later CLI/API consumers can rely on a stable OpenAPI
contract without duplicating domain rules.
